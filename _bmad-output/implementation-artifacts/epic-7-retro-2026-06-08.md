## 5. Key Insights

### I1 — Stable foundations compound: by Epic 7, story implementation is a thin orchestration layer over 6 prior epics' shipped infrastructure

Story 7.1 has 9 NEW source files but adds essentially zero new framework surface — it composes V11 (Story 1.4), `GeneratedTokens` (Story 1.5), `kakaoshare/PngRasterizer` (Story 6.1), `ChatService.publishSystem` REQUIRES_NEW shape (Story 5.4), and `SurvivalStateRepository` (Story 1.3). The architectural depth that takes a quarter to build pays back in epics where new functionality is a thin orchestration layer.

**Implication:** Epic-1-style foundation investment (codegen + tokens + Checkstyle + brand-voice lint) is what makes Epic 7-style velocity possible. Epic 8 should treat its `tools/brand-voice-lint` hard-gate, analytics SDK, and CODEOWNERS-driven release gate with the same foundation-first discipline.

### I2 — In-PR adversarial review caught 7 out of 7 contract-correctness gaps on Story 7.2 — TDD alone would have missed all of them

Story 7.2's 7 review patches:

- 6 are about *contract correctness* (executor saturation under scale, `preExisted` TOCTOU, channel-auth regex, scheduler IT datasource, race-guard test shape, broker-failure invariant).
- 1 is about *test completeness* (missing PNG-bytes assertion).

None of these were "implementation doesn't match test" — TDD passed all of them GREEN. Adversarial review is **the only layer that catches these**. Epic 1 retro I2 predicted this; Epic 7 confirms it twice over.

### I3 — Reviewer-judgment scope-fence extensions worked when they unblocked the next story

Story 7.2 review found that the `JwtChannelInterceptor.ROOM_TOPIC` regex needed `posters` added, OR Story 7.3 would have failed `SUBSCRIBE` at channel auth time. Original AC9 scope fence didn't allow `JwtChannelInterceptor.java` edits. The reviewer extended the fence by 2 lines + documented it as deviation #5.

**Lesson:** scope fences are a discipline tool, not a religion. When the next story is structurally blocked by a 2-line fence extension that the *reviewer caught*, extending the fence in-PR is the right call. The discipline holds because the deviation is *logged* and the *reviewer* (not the implementer) caught it.

### I4 — "Architecture deviations" are eating the architecture doc one story at a time

15 deviations from 3 stories. Zero PRs against `_bmad-output/planning-artifacts/architecture.md`. The deviation log is a parallel architecture spec that lives in the implementation artifacts directory. This is **technically debt-free per individual story** (each deviation is justified, locally consistent, reviewer-accepted) but **debt-laden in aggregate** because the architecture doc no longer reflects the codebase.

**Two responses available:**

(a) Codify a "deviation absorption" sprint at the end of each epic — a single PR that updates architecture.md to match the as-built code. (Same model as Epic 8's release-gate brand-voice review for copy.)

(b) Accept that architecture.md is a *planning* artifact, frozen at W0, and the *living* spec is the union of architecture.md + every story's AC12 deviation log. Then update story-creation skill to grep AC12 entries across all prior stories before authoring new ones.

(a) is more honest; (b) is cheaper. The team has not chosen yet.

### I5 — Compositional CI infrastructure is not free; it decays without an owner

`.github/workflows/be-it-boot-smoke.yml` was the Epic 1 retro T3 deliverable. It worked perfectly in Epics 2–6 because the IT layer it ran was small. Epic 7 grew the layer past the 30-minute cap, and **no one owned bumping the cap**. The follow-up was *logged* (`deferred-work.md`, Story 7.2 PR body) but not *assigned*.

**Generalized:** every workflow file is a system component with a maintainability cost. The cost shows up exactly when the workflow stops doing its job — i.e., when you need it most. Future foundation deliverables (Epic 8's CODEOWNERS release gate, the rumored brand-voice lint hard-gate) need named owners *and a sunset/upgrade SLA* at ship time.
