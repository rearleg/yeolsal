## 4. Challenges (What Didn't Go Well)

### C1 — Story 8.3 shipped to `done` with 5 unresolved `[ ][Review]` items — Epic 8 broke the G1 discipline Epic 7 held perfectly

`8-3-aso-copy-lock-*.md` `### Review Findings` contains **five unchecked `[ ]` items** at merge (PR #105):

1. `[ ] [Review][Decision]` — **iOS subtitle is KR 44 chars / EN 78 chars, but the App Store subtitle limit is 30.** The document claims "all locked strings fit"; they do not. **The ASO copy as written cannot be submitted** — a literal App Store launch blocker.
2–5. `[ ] [Review][Patch]` ×4 on `aso-copy-lint.ts` — duplicate/overlapping/out-of-order marker rejection, marker-derived offset preservation (vs `full.indexOf`), caller-supplied input-path reporting, and `node:assert/strict` import + comment cleanup.

Yet 8.3's completion notes and the session memory both record **"ALL 11 gates GREEN / ZERO deviations."** This is precisely the overclaim pattern that the *same epic's* Story 8.4 review explicitly warned against. The epic taught itself the lesson (8.4) but never went back to fix 8.3.

**Contrast:** 8.1 (9 patches `[x]`), 8.2 (6 `[x]`), 8.4 (6 `[x]`), 8.5 (5 `[x]`). Only 8.3 left items open. Epic 7 retro celebrated G1 as "the cleanest review-discipline epic in the project." It broke one epic later.

**Decision (rearleg, this retro):** keep 8.3 `done`; the iOS subtitle rewrite + 4 aso-copy-lint patches become **critical-path pre-launch action items** (L1 + P1); log the G1 violation here.

### C2 — A1 (CI workflow timeout) is still unresolved after three attempts; "merge on deferral" is now standing precedent

The top Epic 7 retro blocker. Trace:

- **PR #98:** `be-it-boot-smoke.yml timeout-minutes` 30 → **60**. The 60-minute cap was *also* exhausted.
- **PR #99:** Gradle parallel forking + Testcontainers reuse → **fork-deadlock** (root cause: `reuse.enable=true` requires BOTH OS-level and code-level `withReuse(true)`).
- **PR #100:** reverted PR #99.
- The next planned step — JUnit `@Execution(CONCURRENT)` (option g) — has **no trace in the workflow file**; not started.

The workflow file is now at `timeout-minutes: 60` but still cannot complete reliably. **Lesson:** named ownership (rearleg) plus three attempts did not resolve it, because this is a genuinely hard infra problem, not a willpower problem. **Named ownership is necessary but not sufficient** — the refinement of Epic 7 retro G1.

**Decision (rearleg, this retro):** pursue option (g) `@Execution(CONCURRENT)`, but audit `@MockBean` / `@DirtiesContext` / static thread-safety first (A1 carried forward).

### C3 — Analytics backfill never happened; v1 launches with KPIs dark

Story 8.5 instrumented **zero** emission sites; Story 8.1 added only the three onboarding events (`signup.completed`, `onboarding.screen.dwell_ms`, `onboarding.completed`). `revival.*` / `friend_gift.*` / `spectator.*` / `final_three.*` are **all unemitted**. Epic 7 retro Discovery 1 recommended "schedule a small instrumentation pass in Epic 8" — it was not done. The SDK exists, but the revival/friend-gift/spectator→revival/Final-3-share-rate KPIs — the exact loops v1's success criteria depend on — have **no telemetry on launch day**. The reason 8.5 existed (measure KPIs from launch forward) is ~20% realized.

**Decision (rearleg, this retro):** run a **pre-launch backfill pass** wiring the deferred emit sites through 8.5's `AnalyticsService` (L2).

### C4 — A2/A3 (pattern codification + architecture absorption) are now two retros deep with zero progress

`git log` confirms `project-context.md`, `architecture.md`, and `deferred-work.md` were **untouched since 2026-06-08**. Epic 1 retro A1 = Epic 7 retro A2 (codify canonical patterns) = still not started. The 15 architecture deviations from Epic 7 still have 0 absorption PRs, and Epic 8 added more. **Common shape: a "cleanup" item with no forcing deadline.** This is the precise pattern Epic 7 retro's own G1 predicted would not ship.

**Decision (rearleg, this retro):** A2/A3 must be **resolved either way** — execute as a v1-wrap PR, or formally adopt the union-spec model (architecture.md + AC12 deviation logs) and stop carrying it as an open action item.

### C5 — The release-gate (8.4) is shipped but not yet enforcing

8.4's gate needs three post-merge GitHub settings to actually function: real PM/designer **distinct** handles (currently `@rearleg` ×2 placeholder), `BRAND_VOICE_{PM,DESIGNER}_REVIEWERS` repository variables, and a required check on `main` + a `v*` tag ruleset. Until those land, the gate exists only as documentation + an inert workflow.

**Decision (rearleg, this retro):** configure the three GitHub settings as a pre-release action (L3).

## 5. Key Insights

### I1 — Foundation compounding continued: Epic 8's consumer surfaces are thin orchestration over six epics of infrastructure

Onboarding (8.1) reused the SecureStore durable-record pattern (`playedRevivalEvents.ts` shape) and Kakao `pendingInviteCode` bridging (6.2); the share/ASO work composed the brand-voice tooling foundation from Story 1.5. The same Epic-1/Epic-7 insight holds: deep foundation investment makes late-epic features cheap.

### I2 — Retrospective enforcement scales with "named owner + hard deadline" — now two retros of data

Items with a named owner AND a forcing "before Story 8.X" deadline shipped: Discovery 1 (reorder), Pre-2 (SDK decision), T1 (FE baseline). Items without a forcing deadline did not: A2 (codification), A3 (absorption), the backfill pass. **A1 is the instructive exception** — named owner, hard deadline, three attempts, still unresolved — proving the rule's boundary: named ownership concentrates *attention*, but hard infra problems also need a *timeboxed-attempt + escalation* protocol, not just an owner.

### I3 — Adversarial review now checks the honesty of the completion record, not just the code

Story 8.4's review caught (a) a real enforcement gap (CODEOWNERS can't require two roles) and (b) the dev record's own false "ALL gates PASS / ZERO deviations" claim. Story 8.3 made the *same* overclaim and *no review pass corrected it* — which is exactly why it shipped a submit-blocker silently. The differentiator between 8.3 and 8.4 was whether an adversarial pass actually ran and was acted on.

### I4 — "Feature-complete" and "instrumentation-complete" are different launch axes

v1 is feature-complete across 8 epics, but KPI measurability — the hidden axis of launch readiness — is only partially wired. A product can be 100% built and still be unable to tell whether it's working. The analytics backfill gap (C3) is this insight made concrete.
